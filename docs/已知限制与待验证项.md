# 已知限制与待验证项 (Phase 0 & Phase 1)

## 概述
本报告记录了目前 **AI Token Flow Monitor** 在 Phase 0 及 Phase 1 阶段中的已知技术限制、依赖假设以及后续 Phase 2 (Real Adapters & Floating UI) 中待进一步实测验证的具体事项。

---

## 1. 已知技术限制 (Known Limitations)

1. **Codex App Server 实时 WebSocket 接口**:
   - 目前 Phase 0 主要审计并验证了 Codex 本地 `.codex/state_5.sqlite` 数据库及 `.codex/sessions/**/rollout-*.jsonl` 快照。
   - Codex App Server 的实时 WebSocket tokenUsage event 更新频率与长连接机制需在后续接入 `CodexAdapter` 时进行实测，若断开将自动 fallback 至 JSONL 快照。
2. **Claude Code 细粒度流式 Incremental Token**:
   - Claude Code 当前公开的 `.claude/projects/*/*.jsonl` 日志仅在 Assistant Message 完成（Turn Completion）后写入使用量。
   - 因此，Claude 纯静态日志采集下 `TemporalAccuracy` 为 `TurnExact` / `TURN`，无法直接作为 1 秒级 LIVE 流式 Output TPS。
3. **Prefill Timing (IN TPS)**:
   - 绝大多数第三方 Agent 仅提供 `input_tokens` 总量，未暴露服务端的显式 Prefill 起止时间 (`prefill_start_ms`, `prefill_end_ms`)。
   - 引擎目前正确将其标定为 `Effective IN TPS` (`MEASURED`) 或 `Unavailable` (`—`)，在没有精确起止时间时不强制伪造 Prefill TPS。
